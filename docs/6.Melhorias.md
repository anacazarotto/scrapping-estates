# Melhorias no baseline

## 1. Problema observado

- As previsões estavam mudando demais entre execuções.
- O artefato salvo em `pickle` gerava risco de incompatibilidade entre versões do ambiente.
- O baseline anterior dependia de um único modelo, o que aumentava a sensibilidade do resultado.

## 2. Mudança aplicada

- O baseline passou a usar um **ensemble mediano determinístico**.
- Em vez de confiar em um único regressor, o sistema treina vários modelos e usa a **mediana** das previsões.
- O treino agora é **segmentado por tipo**:
  - `Casa`
  - `Apartamento`
- Também foram adicionadas duas limpezas simples:
  - bairros raros viram `outros`
  - valores extremos de área/quartos/vagas/banheiros são clipados por quantis
- O conjunto atual considera:
  - Gradient Boosting
  - Random Forest
  - Ridge
  - XGBoost, quando disponível
  - CatBoost, quando disponível

## 3. Ganho prático

- A mediana reduz o impacto de um modelo isolado destoante.
- Separar por tipo reduz mistura de padrões muito diferentes.
- Agrupar bairros raros diminui ruído em regiões com pouca amostra.
- O clipping evita que valores muito fora do padrão dominem o ajuste.
- As previsões ficam mais estáveis para entradas parecidas.
- O comportamento do baseline fica mais próximo de um modelo "mediano", com menor oscilação.

## 4. Persistência do modelo

- O baseline passou a ser salvo em **JSON portátil**.
- Mesmo usando a extensão `.pkl`, o conteúdo agora é serializável e legível.
- Isso reduz problemas de carregamento entre versões diferentes de bibliotecas.

## 5. Compatibilidade

- O carregamento ainda aceita artefatos antigos.
- Também há compatibilidade com o formato linear legado baseado em coeficientes.

## 6. Resultado esperado

- Menos diferença entre previsões repetidas.
- Menor dependência da versão exata do ambiente.
- Baseline mais simples de manter e reaproveitar.
