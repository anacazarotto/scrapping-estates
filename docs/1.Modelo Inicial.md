# Modelo de preço de imóveis

Este projeto passa a ter três passos antes da previsão:

1. **Unificação dos bancos coletados por código**
2. **Normalização dos dados**
3. **Treinamento do modelo preditivo**

## 1. Unificação

O comando `scripts_predict/imoveis_ml.py unify` junta todos os bancos `imoveis_??_??_????.db` em `imoveis_unificado.db`.

Ele usa a parte numérica do `id` como `codigo` e mantém um único registro por imóvel, preservando também:

- lista dos `id` de origem;
- lista dos bancos de origem;
- quantidade de ocorrências.

## Tipos de imóvel aceitos

O catálogo usado no modelo fica limitado a:

- Apartamento
- Casa
- Terreno
- Cobertura
- Chácara
- Prédio
- Studio
- Comercial
- Lançamento
- Outros

Use:

```bash
python3 scripts_predict/imoveis_ml.py types
```

## 2. Normalização

O banco original (`imoveis_dd_mm_aaaa.db`) contém registros vindos de várias imobiliárias, com variações de escrita e imóveis repetidos entre fontes diferentes.

O script `scripts_predict/imoveis_ml.py normalize` lê a tabela `imoveis` do banco unificado e gera `imoveis_normalizados.db` com uma tabela consolidada `imoveis_normalizados`.

### Regras aplicadas

- imóveis sem preço são ignorados;
- campos nulos numéricos são tratados como `0`;
- o tipo do imóvel é padronizado (`Apartamento`, `Casa`, `Terreno`, `Cobertura`, `Chácara`, `Prédio`);
- `area_total` e `area_privada` são mantidas separadamente;
- registros são agrupados por:
  - cidade
  - bairro
  - tipo do imóvel
  - área arredondada
  - quartos
  - banheiros
  - vagas

Quando há mais de um imóvel no mesmo grupo, eles são consolidados em um único registro:

- preço final = mediana dos preços;
- área final = mediana das áreas;
- bairro/cidade/tipo = valor mais frequente;
- o registro consolidado guarda também os ids de origem.

## 3. Modelo preditivo

O script `scripts_predict/imoveis_ml.py train` usa o banco normalizado e treina um modelo de regressão linear com regularização **Ridge**.

### Variáveis de entrada

- `area_total`
- `area_privada`
- `bairro`
- `tipo_imovel`
- `quartos`
- `banheiros`
- `vagas`

### Como o modelo funciona

- `bairro` e `tipo_imovel` são transformados em variáveis categóricas com **one-hot encoding**;
- `area_total` e `area_privada` entram separadamente no modelo, junto com as demais variáveis numéricas;
- o preço alvo é transformado com `log1p(preco)` para reduzir distorção causada por imóveis muito caros;
- o modelo aprende os coeficientes por fórmula fechada, usando regularização para evitar overfitting.

Na previsão, o modelo:

1. normaliza os campos recebidos;
2. monta a mesma estrutura de features do treino;
3. calcula o valor previsto em escala log;
4. aplica `expm1` para voltar ao preço em reais.

## 4. Uso

### Gerar o banco normalizado

```bash
python3 scripts_predict/imoveis_ml.py unify --pattern imoveis_??_??_????.db --output-db imoveis_unificado.db
python3 scripts_predict/imoveis_ml.py normalize --source-db imoveis_unificado.db --output-db imoveis_normalizados.db
```

### Treinar o modelo

```bash
python3 scripts_predict/imoveis_ml.py train --normalized-db imoveis_normalizados.db --model-path modelos/preco_imovel_modelo.json
```

### Fazer uma previsão

```bash
python3 scripts_predict/imoveis_ml.py predict \
  --model-path modelos/preco_imovel_modelo.json \
  --area-total 80.2 \
  --area-privada 80.2 \
  --bairro "Vila Real" \
  --tipo-imovel Apartamento \
  --quartos 3 \
  --banheiros 1 \
  --vagas 2
```

## 4. Resultado atual

O modelo é simples e explicável, mas ainda pode melhorar bastante com:

- mais variáveis de contexto;
- tratamento melhor de bairros muito raros;
- remoção de outliers;
- validação cruzada mais forte;
- modelos não lineares no futuro.

O comparativo de experimentos ficou em `2.Comparativo de Modelos Inicial.md`.

## Baseline atual

O baseline padrão do projeto agora é:

- imóveis do tipo **Casa** e **Apartamento**;
- remoção de outliers por IQR;
- modelo **Gradient Boosting**;
- alvo em `preco` (sem log);
- parâmetros: `n_estimators=500`, `learning_rate=0.05`, `max_depth=3`.
